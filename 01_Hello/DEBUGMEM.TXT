第一次作业（2）：用 DEBUG 把代码和数据写入内存后执行

一、进入 DEBUG

    C:\>debug
    -

    启动后 CS、DS、ES、SS 指向同一段，IP = 0100h，可以直接在
    CS:0100 处写入程序。下面的段地址 073Fh 只是示例，实际值随环境变化。

二、用 -e 写入数据

    -e 0200 48 65 6C 6C 6F 2C 20 57 6F 72 6C 64 21 24

    0200h 起依次是：

    48 65 6C 6C 6F 2C 20 57 6F 72 6C 64 21 24
    H  e  l  l  o  , 空格 W  o  r  l  d  !  $

    最后一个 24h 是 DOS 字符串的结束符 '$'。

三、用 -e 写入代码

    -e 0100 BA 00 02 B4 09 CD 21 B8 00 4C CD 21

    写入的机器码和汇编语句一一对应：

    0100  BA 00 02     MOV DX,0200
    0103  B4 09        MOV AH,09
    0105  CD 21        INT 21
    0107  B8 00 4C     MOV AX,4C00
    010A  CD 21        INT 21

    BA 00 02 是 MOV DX,立即数，立即数为 0200h，指向刚写入的字符串；
    B4 09 把 09h 送 AH，选择 DOS 的显示字符串功能；
    CD 21 是 INT 21h；B8 00 4C 把 4C00h 送 AX，选择结束程序功能；
    最后的 CD 21 把控制权交回 DOS。

四、用 -u 反汇编检查

    -u 0100 010B
    073F:0100 BA0002        MOV DX,0200
    073F:0103 B409          MOV AH,09
    073F:0105 CD21          INT 21
    073F:0107 B8004C        MOV AX,4C00
    073F:010A CD21          INT 21

    -u 把内存里的机器码翻译回汇编语句，可以和第三步写入的字节逐条对照。

五、运行

    -g
    Hello, World!
    Program terminated normally
    -q

    -g 从 CS:IP（0100h）开始执行；程序用 INT 21h 的 4Ch 功能结束后，
    DEBUG 显示 Program terminated normally，回到 '-' 提示符。

六、用 -a 汇编指令并观察标志寄存器

    另开一次 DEBUG，用 -a 直接输入汇编语句：

    -a
    073F:0100 mov ax,8000
    073F:0103 add ax,8000
    073F:0106
    -t
    AX=8000  BX=0000  CX=0000  DX=0000  SP=00FD  BP=0000  SI=0000  DI=0000
    DS=073F  ES=073F  SS=073F  CS=073F  IP=0103  NV UP EI PL NZ NA PO NC
    073F:0103 050080          ADD     AX,8000
    -t
    AX=0000  BX=0000  CX=0000  DX=0000  SP=00FD  BP=0000  SI=0000  DI=0000
    DS=073F  ES=073F  SS=073F  CS=073F  IP=0106  OV UP EI PL ZR NA PE CY

    对应的控制台截图见 assets/debug.jpg。

七、标志位分析

    第一条 -t 执行 mov ax,8000 后，AX=8000h，标志位 NV UP EI PL NZ NA PO NC：
    OF=0、SF=0、ZF=0、PF=0、CF=0。MOV 指令不影响标志位，这一行显示的是
    执行前的标志状态。

    第二条 -t 执行 add ax,8000 后，AX=0000h，标志位 OV UP EI PL ZR NA PE CY：

      OF=1（OV）：8000h 作为 16 位有符号数是 -32768，两个负数相加为
                  -65536，超出 16 位有符号数的范围 -32768~32767，发生
                  有符号溢出，因此 OF=1。

      SF=0（PL）：结果的最高位是 0，看起来像正数。两个负数相加却得到
                  一个“正”的结果，这就是常说的“负负得正”。实际数学结果
                  -65536 仍是负数，只是低 16 位被截断成 0000h 后，符号位
                  变成了 0，并不是真的得到了正数。

      CF=1（CY）：从无符号数看，8000h + 8000h = 10000h，超过 16 位能表示
                  的最大值 FFFFh，产生进位，因此 CF=1。

      ZF=1（ZR）：结果的低 16 位是 0000h，结果为零。
      PF=1（PE）：结果低 8 位是 00h，其中 1 的个数为 0（偶数），偶校验。
      AF=0（NA）：低 4 位没有向高 4 位进位。

    OF 和 CF 的含义不同：OF 管有符号数溢出，CF 管无符号数进位。
    本例中两个标志同时为 1，但原因分别是“有符号结果超出范围”和
    “无符号结果产生进位”。

八、和源程序对照

    HELLO.EXE 是 .EXE 程序，用 DEBUG 装入后可以直接反汇编：

    C:\>debug HELLO.EXE
    -u

    HELLO.ASM 中的语句和机器码对应关系如下：

    源语句                 机器码       说明
    mov ax, data           B8 xx xx     段地址由 DOS 装载时按重定位表填入
    mov ds, ax             8E D8        把 AX 送 DS
    mov dx, offset msg     BA 00 00     msg 在数据段内的偏移为 0
    mov ah, 09h            B4 09        功能号 09h
    int 21h                CD 21        调用 DOS
    mov ax, 4c00h          B8 00 4C     功能号 4Ch，返回码 00h
    int 21h                CD 21        调用 DOS

    mov ax, data 后面的两个字节是数据段的段地址，链接时先留空，
    由 DOS 在装载时根据重定位表填写，所以每次运行看到的数值可能不同；
    mov dx, offset msg 后面的 0000h 是 msg 在数据段内的偏移，与装载位置无关。
